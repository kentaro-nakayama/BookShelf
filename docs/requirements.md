# 本棚アプリ 要件定義書

- 作成日: 2026-10-02
- ステータス: 確定（機能要件・技術スタック合意済み）

## 1. プロジェクト概要

読んだ本・読みたい本を登録し、感想やレビューをまとめて管理できる本棚アプリ。
書籍情報は外部APIから自動取得し、ユーザーは評価・感想・ジャンル・読書ステータスを記録できる。

## 2. 目的・ゴール

- 自分の読書記録を一元管理できるようにする
- 本の感想を後から振り返りやすい形で蓄積する
- 複数ユーザーがそれぞれ自分の本棚を持てるようにする

## 3. 想定ユーザー

- 複数ユーザー対応（各ユーザーがアカウントを持ち、自分専用の本棚を管理する）
- 他ユーザーの本棚を閲覧する機能は現時点ではスコープ外（9章参照）

### 3.1 主な利用環境（スマートフォン前提）

- **主な利用シーンはスマートフォンでの使用を想定する**（書店・図書館・移動中などに、その場で本を検索して登録する使い方が中心）
- PC（デスクトップブラウザ）でも利用できるが、設計・UI検討時はスマートフォンを第一優先（モバイルファースト）とする
- 対象ブラウザ: iOS Safari / Android Chrome を主対象、PCは各モダンブラウザの最新版
- 縦画面（ポートレート）での片手操作を基本とし、タップ領域・フォントサイズ・入力フォームはスマートフォンで扱いやすいサイズを確保する

## 4. 技術スタック

| 項目 | 選定内容 |
|---|---|
| フロントエンド/バックエンド | Next.js（App Router）+ TypeScript |
| データベース | PostgreSQL（Vercel Marketplace経由の Neon） |
| 認証 | Auth.js（NextAuth） |
| デプロイ先 | Vercel |
| 書籍検索API | 楽天ブックスAPI（優先）→ ヒットしなければ Google Books API にフォールバック |
| UIコンポーネント | shadcn/ui（シンプル・モダンなデザイン） |

### 選定理由・補足
- Next.js + Vercelの組み合わせは環境構築・デプロイが一本化でき、個人〜小規模複数ユーザー向けアプリに適している。
- `create-next-app`でのプロジェクト作成時にTypeScriptを採用。開発者はJavaScript経験のみだが、Next.js標準テンプレートに合わせてTypeScriptで進める（型エラーで詰まった際は都度サポートする）。
- 書籍検索は日本語書籍の精度が高い楽天ブックスAPIを優先し、ヒットしない場合に書籍カバー範囲の広いGoogle Books APIで補完する。

## 5. 機能要件

### 5.1 認証機能
- Auth.js（NextAuth）による Google ログインのみ（メール+パスワード認証は実装しない）
- ログイン／ログアウト、セッション管理

### 5.2 書籍検索・登録機能
- タイトル・著者名等で書籍を検索
- 検索フロー: 楽天ブックスAPIで検索 → 0件の場合はGoogle Books APIで再検索
- 検索結果から書籍を選択し、自分の本棚に登録（タイトル・著者・表紙画像・出版社等を自動取得）
- 本棚登録時に読書ステータスを設定（下記5.4）

### 5.3 本棚管理機能（CRUD）
- 登録した本の一覧表示
- 本の詳細表示・編集・削除
- ステータス・ジャンル・評価での絞り込み検索

### 5.4 読書ステータス管理
- ステータス種別: 「読みたい」「読書中」「読了」
- ステータスはいつでも変更可能

### 5.5 感想・レビュー機能
- 星評価（5段階）
- 自由記述の感想文

### 5.6 ジャンル分類機能
- あらかじめ用意した固定の選択肢（小説・ビジネス・自己啓発・技術書・エッセイ・その他）から選ぶ方式
- 1冊の本に複数のジャンルを設定可能
- ジャンルの選択肢はDBのマスタデータとして管理し、追加・変更は開発者がマイグレーション/シードデータを更新して行う（ユーザーがアプリ上で追加する機能は持たない）

## 6. 画面一覧（初期案）

1. ログイン／サインアップ画面
2. 本棚一覧画面（ステータス別・ジャンル別フィルタ）
3. 書籍検索・登録画面
4. 本の詳細・感想編集画面
5. プロフィール／設定画面（任意・詳細は今後検討）

## 7. データモデル（初期案）

- **users**: id, name, email, created_at
- **books**: id, external_source(rakuten/google), external_id, isbn, title, author, publisher, published_date, thumbnail_url, created_at
- **user_books**: id, user_id, book_id, status(読みたい/読書中/読了), rating(1-5, nullable), review_text(nullable), created_at, updated_at
- **genres**: id, name（固定マスタ。初期値: 小説・ビジネス・自己啓発・技術書・エッセイ・その他）
- **user_book_genres**: user_book_id, genre_id（中間テーブル。1冊に複数ジャンル設定可）

※ 正規化・カラム詳細は実装時に調整

## 8. 非機能要件

- レスポンシブ対応（スマートフォン優先・PCにも対応）。ブレークポイント設計はモバイルファーストで行う
- スマートフォン利用を想定した操作性の確保
  - タップ対象は十分な大きさ（目安44px以上）を確保し、誤タップを防ぐ
  - 横スクロールが発生しないレイアウトとする
  - iOS Safari特有の表示崩れ（セーフエリア、バウンススクロール、入力時の自動ズーム等）に配慮する
- モバイル回線での利用を想定し、表紙画像などの読み込みが過度に重くならないようにする
- 未ログイン時は本棚関連ページへのアクセスを制限
- 外部API呼び出し時のローディング表示・エラーハンドリング
- Vercelの自動スケールを前提とし、個人〜小規模複数ユーザー利用を想定した性能で十分とする

## 9. スコープ外（MVP外・将来検討）

- 他ユーザーの本棚閲覧・SNS的な共有機能
- バーコードスキャンによるISBN読み取り登録
- 読書記録の統計・グラフ化
- レコメンド機能

## 10. 未確定事項（今後相談して確定する）

- 現時点で未確定の事項はなし（機能要件・技術スタックは確定済み）
- 楽天ブックスAPIのアプリID取得は、実装フェーズで書籍検索機能に着手するタイミングで行う

## 11. ジャンル管理の運用方針

- ジャンルは開発者がコード（マイグレーション/シードデータ）側で管理する固定マスタとする
- ユーザーからの「このジャンルを追加してほしい」という要望は、開発者が都度コードに反映しデプロイすることで対応する
- 将来的にユーザー自身がジャンルを追加できるようにしたい場合は、別途管理画面機能として検討する
